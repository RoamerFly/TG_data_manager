# UI 元素与文案清单

> 只列**界面上存在哪些元素、显示什么文案、什么条件下出现**。
> 布局、尺寸、配色、栅格一律不涉及，交由设计方决定。
> `【动态】` = 运行时填充的内容；`【条件】` = 特定状态才出现。

## 7. 文件卡片

### 元素清单

| 元素 | 说明 |
|---|---|
| 复选框 | 勾选不触发预览 |
| 缩略图 | 图片/视频/贴纸有缩略图；其余显示分类占位图 |
| 播放遮罩 | 半透明播放三角【条件：视频类且非分片】 |
| 类别徽标 | 【动态】取自后端类目值，当前直接显示英文：`image` `video` `audio` `sticker` `unknown` |
| 状态标签 | 见下表【条件】 |
| 文件名 | 【动态】优先真实文件名，没有则显示缓存 ID；单行截断 |
| 副标题 | 【动态】`<类型标签> · <文件大小>`，例如 `视频 · 24.5 MB` |

### 状态标签全集（右上角）

| 文案 | 出现条件 |
|---|---|
| `已重建` | 大视频，已重建且完整 |
| `已重建 · 局部` | 大视频，已重建但不完整 |
| `完整` | 大视频，缓存已完整 |
| `合成率 XX.XX%`【动态，两位小数】 | 大视频，不完整 |
| `大视频` | 大视频，无合成率数据时兜底 |
| `可合成` | 分片，且所属视频已完整 |
| `分片` | 分片，且所属视频不完整 |
| `孤立` | 分片，找不到所属视频 |
| `下载` | 下载视图的所有卡片 |

> 产品规则：一个视频只占一张卡，已归属的分片**不再单独显示**；
> 排序为 完整大视频 → 不完整大视频（合成率降序）→ 其他文件。

## 10. 预览弹窗

### 通用元素

- 标题：【动态】文件名；右上角关闭 `×`
- 内容区：见下方分支
- Telegram 绑定区：见 10.2【条件】
- 底部信息栏：【动态】由 `·` 连接的元信息，例如 `视频 · 24.5 MB · 可播 38.2s`
- 底部按钮：`前往 Telegram 播放`（次按钮）、`删除缓存`（危险按钮）、`导出文件`（主按钮）
  - 下载文件预览时：隐藏 `前往 Telegram 播放`，`导出文件` 改为 `在浏览器打开`

### 10.1 内容分支

**图片** — 大图，点击可切换缩放。

**普通视频（缓存不完整）**
> `此视频缓存不完整 (缺少元数据 moov)`
> `可能是 Telegram 未完成下载`
> `可尝试导出后用 VLC 播放器修复`

**大视频 · 已重建** — 播放区 + 按钮 `重新重建`
信息栏：`大视频 · <大小> · 已重建 (moov 前置)`，不完整时追加 ` · 局部片段`

**大视频 · 分片完整，可重建**
- 标题：`大视频缓存 (分片完整, 可重建)`
- 数据项：`估算大小` `已知分块` `需要分片` `已缓存`
- 图例：`● 已缓存 (N)` `● 缺失 (N)`【动态】
- 提示：`所有分片齐全, 点击下方按钮重建并播放`
- 按钮：`重建并播放`（主按钮）

**大视频 · 分片不完整**
- 标题：`大视频缓存 (分片不完整)`
- 数据项：同上，另加 `可播时长`
- 缺失清单：`缺失分片: [1, 5, 9]`；超 20 个时 `缺失分片: [1, 5, ...] ... 共 N 个`
- 警告：`缓存分片不足 (缺 N 分片)`
- 说明：`导出时会只输出从文件开头连续覆盖到的那一段, 时长约 Ns；缺失的区段不会被写成零数据, 因此播放不会在中途卡死或黑屏。`
- 引导：`想在 Telegram Desktop 里播放该视频以补全缓存分片, 重新扫描后即可导出完整时长`
- 按钮：`导出可播放片段`（主按钮）

**分片可视化组件**（上面两种大视频都有）
一串方格表示分片：首格为 Header；每格悬浮提示 `分片 N · <大小> · <文件名>` 或 `分片 N · 缺失`

**8MB 视频分片**
- `8MB 视频分片` + `分片 #N · <大小>`
- 有归属：`归属大视频: <文件名>` + 按钮 `查看大视频`
- 无归属：`Cache Key: <值>` + `(未找到对应 header)`

**TGS 动画贴片** — Lottie 动画；失败文案：
`Lottie 渲染失败: <错误信息>` / `动画贴片解压失败<br>可尝试导出查看`

**未知文件 / 碎片**
> `未知文件类型`
> `可能是未完成下载的碎片数据`
> 附 `头部十六进制:` + 等宽字体的十六进制预览框

**加载失败** — `加载失败: <错误信息>`

**视频播放异常浮层**
- 中断检测：`播放中断: 已播到 Ns / <总时长>` / `数据不再到达 —— 可能是缓存里这一段缺失, 或文件被截断。` / `可尝试"重新重建", 或用播放器打开导出的文件确认。`
- 致命错误，按错误码对应：`格式不受支持或数据损坏` `数据已损坏` `网络/读取中断` `加载被中止`

### 10.2 Telegram 绑定区【条件：缓存视图 + 视频类 + 非分片】

**未绑定**
- 标签 `绑定来源`
- 输入框，占位符 `https://t.me/频道名/消息号`
- 按钮 `绑定`
- 说明：`仅缓存未下载的视频无法自动定位原消息 —— 粘贴原视频的 t.me 链接绑定一次, 之后可一键跳转回去播放、补全缓存分片。一条消息里有多个视频时, 链接末尾加上 ?single&t=序号 (如第 4 个就写 ?single&t=4), 才能直接定位到那一个`

**已绑定**
- 标签 `Telegram 来源` + 链接文本
- 【条件】相册来源时显示橙标签 `相册第 N 个`
- 按钮 `解绑`

### 10.3 预览内的过程态

| 场景 | 文案 |
|---|---|
| 重建中 | `正在重建大视频... (可能需要数秒)` |
| 导出局部片段中 | `正在重建可播放片段... (只写出连续覆盖的部分, 不做零填充)` |
| 导出局部成功 | `已导出局部片段 · 实际可播 Ns, 缺失区段未写入, 播放会在此结束` + 按钮 `重新重建` |
| 重建失败 | `重建失败` + 原因 + `提示: 在 Telegram Desktop 中播放该视频可以补全缓存分片, 重新扫描后再试` |
| 导出失败 | `导出失败` + 原因 + `若提示 moov 未缓存, 说明连文件的索引都没缓存下来, 目前无法生成可播放文件` |

## 13. 设置弹窗

标签 / 输入框 / 提示逐组对照：

| 标签 | 输入框占位符 | 说明文字 |
|---|---|---|
| `Telegram 数据目录 (tdata 路径)` | `D:\Software\Telegram Desktop\tdata` | `缓存文件来源目录，修改后将需要重新扫描` |
| `Telegram 下载目录` | `C:\Users\你的用户名\Downloads\Telegram Desktop` | `下载文件来源目录，留空则自动检测` |
| `Telegram 本地密码 (Passcode)` | `仅当 Telegram 设置了本地密码时填写` | 已设置时：`当前已设置本地密码。如需清除，保存时留空即可。`<br>未设置时：`留空表示无密码。设置后用于解密缓存密钥，改动需重新扫描。` |

- 分区标题：`清理 (会先预览再二次确认)`
- 按钮：`清理孤儿文件` `打开导出目录`
- 危险/次要按钮：`清空 Telegram 缓存`（危险）`清空下载目录`（危险）`清空应用缓存`
- 说明一：**清空 Telegram 缓存**：只删 tdata 下 cache 与 media_cache 里的缓存文件（保留 version / binlog）。**不会**触碰账号数据 key_datas 与 D877F783D5D3EF8C，聊天记录、设置、登录态都不受影响。建议先退出 Telegram Desktop 再执行。
- 说明二：**清空下载目录**：删除下载目录里的全部文件。**清空应用缓存**：只清本工具自己产出的 exports/ 与 thumbnails/。两者均不可恢复。
- 底部：`保存`（主按钮）

## 15. 二次确认弹窗文案全集（当前为浏览器原生 confirm，建议改为自定义弹窗）

1. 删除缓存文件：`确认删除此缓存文件？` / `删除后将从磁盘上移除原始缓存数据，此操作不可恢复。`

3. 批量删除：`确认删除选中的 N 个文件？` / `此操作不可恢复。`

5. 清空导出：`确认清空所有导出文件？此操作不可恢复。`

   - 标题：`确认清空「<目标名>」？`（目标名取 `Telegram 缓存` / `下载目录` / `应用缓存`）

   - `示例文件: …`

## 17. 需要保留的交互约定

- 点卡片开预览，点复选框只勾选
- 快捷键：`Ctrl+A` 全选当前页、`/` 聚焦搜索、`ESC` 关闭弹窗（均需焦点不在输入框）
- 点击遮罩关闭弹窗
- 主题选择本地持久化，默认浅色
- 执行中的批量按钮临时变为「取消」按钮，并显示进度 `N/M`
- 缩略图懒加载；预览大图点击可缩放

---

## 18. 建议一并改掉的元素问题

1. 卡片类别徽标目前是英文 `image`/`video`/`audio`/`sticker`/`unknown`，与全中文界面不一致，建议汉化。
2. 有 7 处使用浏览器原生 `confirm()`，风格割裂（见第 15 节）。
3. 危险按钮与次按钮视觉差异偏弱，删除类操作建议进一步强化。
4. 右侧工具栏按钮最多 7 个，建议考虑「更多操作」收纳。
