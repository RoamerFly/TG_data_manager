### 8.2 元素说明

| 位置 | 内容 | 说明 |
|---|---|---|
| 复选框 `.file-card-checkbox` | — | 点选不触发预览 |
| 缩略图 `.file-card-thumb` | 图片/视频/贴纸走缩略图 API；无缩略图时显示分类占位图 | 加载失败用占位图兜底 |
| 播放遮罩 `.play-overlay` | 白色播放三角（32px） | 仅视频类（非分片）显示 |
| 类别徽标 `.file-card-badge` | 【动态】后端 `category` 原值：`image` / `video` / `audio` / `sticker` / `unknown` | **目前是英文未汉化，重绘时可改为中文：图片/视频/音频/贴纸/未知** |
| 文件名 `.file-card-name` | 【动态】优先显示真实文件名 `display_name`，否则缓存文件 ID | 有真实名时加 `has-display-name` 样式 |
| 元信息 `.file-card-meta` | 【动态】`<类型标签>` + `<文件大小>` | 例：`视频 · 24.5 MB` |

### 8.3 右上角状态标签全集（重要）

缓存视图，按优先级渲染：

| 标签 | 文案 | 条件 | 建议色 |
|---|---|---|---|
| `.tag-rebuilt` | `已重建` | 大视频 + 已重建 + 完整 | 蓝 |
| `.tag-rebuilt` | `已重建 · 局部` | 大视频 + 已重建 + 不完整 | 蓝灰 |
| `.tag-complete` | `完整` | 大视频，缓存覆盖率 100% | 绿 `--success` |
| `.tag-rate` | `合成率 XX.XX%`【动态，两位小数】 | 大视频，不完整 | 橙 `#e67e22` |
| `.tag-large` | `大视频` | 大视频，无合成率数据（兜底） | 蓝 |
| `.tag-complete` | `可合成` | 分片且能归属到完整的父视频 | 绿 |
| `.tag-slice` | `分片` | 分片且父视频不完整 | 灰蓝 |
| `.tag-orphan` | `孤立` | 分片找不到父视频 | 灰 |

下载视图：

| 标签 | 文案 |
|---|---|
| `.tag-download` | `下载` |

> 排序规则（产品逻辑，重绘请保留）：完整大视频 → 不完整大视频（按合成率降序）→ 其余文件。
> 归属到某个视频的分片**不再单独成卡**，只显示该视频一条记录。

分类占位（无法生成缩略图时）：图片 / 视频 / 音频 / 贴纸 / 未知 各一个图标 + 分类暗示。

## 11. 预览弹窗 `#preview-modal`（最复杂）

### 11.1 固定结构

| 区域 | 内容 |
|---|---|
| 标题 `#preview-title` | 【动态】文件名（下载预览也是文件名） |
| 关闭按钮 | `×` |
| 内容区 `#preview-body` | 见下方分支 |
| Telegram 绑定区 `#telegram-bind-box` | 见 11.3 |
| 底部左 `#preview-info` | 【动态】竖线分隔的元信息，例：`视频 · 24.5 MB · 可播 38.2s` |
| 底部右按钮组 | `前往 Telegram 播放`（次按钮）/ `删除缓存`（危险按钮）/ `导出文件`（主按钮） |

> 下载文件预览时：`前往 Telegram 播放` 隐藏，`导出文件` 文案改为 `在浏览器打开`。

### 11.2 内容区分支（按文件类型/状态）

**图片** — 大图，点击切换缩放。

**普通视频** — `<video controls autoplay>`。缓存不完整（缺 moov）时：
> `此视频缓存不完整 (缺少元数据 moov)`<br>`可能是 Telegram 未完成下载`<br>`可尝试导出后用 VLC 播放器修复`

**大视频 · 已重建** — 直接播放 + 右下角按钮 `重新重建`；信息栏：
`大视频 · <大小> · 已重建 (moov 前置)`，不完整时追加 ` · 局部片段`。

**大视频 · 分片完整但未重建** — 显示分片可视化（见下）+：

- 标题：`大视频缓存 (分片完整, 可重建)`
- 数据项（标签 → 值）：`估算大小` / `已知分块` / `需要分片` / `已缓存`
- 图例：`● 已缓存 (N)` `● 缺失 (N)`
- 提示：`所有分片齐全, 点击下方按钮重建并播放`
- 按钮：`重建并播放`（主按钮）

**大视频 · 分片不完整** — 显示分片可视化 +：

- 标题：`大视频缓存 (分片不完整)`
- 数据项同上，另加 `可播时长`（`Ns`）
- 缺失清单：`缺失分片: [1, 5, 9]`（超过 20 个时 `缺失分片: [1, 5, ... ] ... 共 N 个`）
- 警告条：`缓存分片不足 (缺 N 分片)`
- 说明：`导出时会**只输出从文件开头连续覆盖到的那一段**, 时长约 Ns；缺失的区段不会被写成零数据, 因此播放不会在中途卡死或黑屏。`
- 引导：`想在 Telegram Desktop 里播放该视频以补全缓存分片, 重新扫描后即可导出完整时长`
- 按钮：`导出可播放片段`（主按钮）

**分片可视化** `.slice-cells`：一串小方格，每格代表一个分片，绿=已缓存 / 红空=缺失，
首格标 `0`（Header），每格 tooltip：`分片 N · <大小> · <文件名>` 或 `分片 N · 缺失`。

**8MB 视频分片**：
> 图标 + `8MB 视频分片`<br>`分片 #N · <大小>`
>
> 有父视频时：`归属大视频: <文件名>` + 按钮 `查看大视频`
> 无父视频时：`Cache Key: <值>` + `(未找到对应 header)`

**TGS 动画贴片** — lottie-web 渲染；失败时：
> `Lottie 渲染失败: <错误信息>` / `动画贴片解压失败<br>可尝试导出查看`

**未知文件 / 碎片**：
> `未知文件类型`<br>`可能是未完成下载的碎片数据`
>
> 附 `头部十六进制:` + hex 预览框（等宽字体）

**加载失败**：`加载失败: <错误信息>`

**视频播放错误提示**（叠加在视频上）：

- 致命错误：`<说明>`，其中 code 对应：`格式不受支持或数据损坏` / `数据已损坏` / `网络/读取中断` / `加载被中止`
- 中断检测（播放卡住）：`播放中断: 已播到 Ns / <总时长>`<br>`数据不再到达 —— 可能是缓存里这一段缺失, 或文件被截断。`<br>`可尝试"重新重建", 或用播放器打开导出的文件确认。`

### 11.3 Telegram 绑定区

**未绑定（仅缓存视图 + 视频类 + 非分片）**

- 标签 `绑定来源`
- 输入框 placeholder：`https://t.me/频道名/消息号`
- 按钮 `绑定`
- 说明文字：
  > 仅缓存未下载的视频无法自动定位原消息 —— 粘贴原视频的 t.me 链接绑定一次, 之后可一键跳转回去播放、补全缓存分片。一条消息里有多个视频时, 链接末尾加上 `?single&t=序号` (如第 4 个就写 `?single&t=4`), 才能直接定位到那一个

**已绑定**

- 标签 `Telegram 来源` + 链接文本（可 hover 显示完整 t.me 地址）
- 相册来源时额外橙标签 `相册第 N 个`
- 按钮 `解绑`

### 11.4 预览内的过程性界面

| 场景 | 文案 |
|---|---|
| 重建中 | spinner + `正在重建大视频... (可能需要数秒)` |
| 导出局部中 | spinner + `正在重建可播放片段... (只写出连续覆盖的部分, 不做零填充)` |
| 重建成功 | Toast：`重建成功: <文件名> · 时长 Ns · 局部片段?` |
| 重建失败 | `重建失败<br><原因>` + `提示: 在 Telegram Desktop 中播放该视频可以补全缓存分片, 重新扫描后再试` |
| 导出局部成功 | 提示条：`已导出局部片段 · 实际可播 Ns, 缺失区段未写入, 播放会在此结束` + 按钮 `重新重建` |
| 导出失败 | `导出失败<br><原因>` + `若提示 moov 未缓存, 说明连文件的索引都没缓存下来, 目前无法生成可播放文件` |

## 16. 原生 confirm 对话框文案（建议重绘时改造成自定义弹窗）

1. 删除缓存文件：`确认删除此缓存文件？\n删除后将从磁盘上移除原始缓存数据，此操作不可恢复。`
2. 删除下载文件：`确认删除下载文件 "<文件名>" ？\n此操作将从磁盘上移除文件，不可恢复。`
3. 批量删除：`确认删除选中的 N 个文件？\n此操作不可恢复。`
4. 删除导出文件：`确认删除 <文件名>？`
5. 清空导出：`确认清空所有导出文件？此操作不可恢复。`
6. 清理孤儿：`确认清理孤儿文件？\n将删除不属于当前扫描结果的缩略图和导出文件。此操作不可恢复。`
7. 清空某目标（最重要，两步确认）：
   ```
   确认清空「<目标名>」？

   将清空以下目录:
   <目录1>
   <目录2>

   共 N 个文件，约 <大小>
   示例文件: a, b, c

   此操作不可恢复。账号数据 (key_datas / D877F783D5D3EF8C)、聊天记录与登录态不会被删除。
   ```
   目标名取值：`Telegram 缓存` / `下载目录` / `应用缓存`

## 18. 已知的 UI 问题（重绘时可一并优化）

1. **类别徽标是英文**（`image`/`video`/`audio`/`sticker`/`unknown`），与界面其余中文不一致。
2. **大量使用浏览器原生 `confirm()`**，视觉与整体风格割裂（第 16 节 7 处）。
3. 多个渲染存在**同一元素被后写覆盖**的历史问题（例如预览信息栏文案被通用分支冲掉），
   新 UI 建议按"状态组件"拆分而不是字符串拼接。
4. 工具栏按钮较多（最多 7 个），窄屏会挤压，建议考虑收纳到「更多操作」菜单。
5. 删除/清空类操作已有二次确认，但**危险按钮与次按钮视觉差异偏弱**，可加强。
